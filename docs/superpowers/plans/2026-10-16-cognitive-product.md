# 个人认知体检产品能力实施计划

> **For agentic workers:** Use superpowers:executing-plans for integration and verification; independent modules may be delegated with explicit file ownership.

**Goal:** 将新版需求中的长期重复、情绪观察、主题整理、小时及长期报告、按需信息补全接入可运行产品。

**Architecture:** 复用已有采集、观点结构和历史比较，新增带原文依据的可选情绪结构及报告投影。提醒使用历史联合条件；补全由用户主动触发，外部来源始终与已浏览记录隔离。保留旧 JSON 兼容，不迁移或补造历史数据。

**Tech Stack:** Kotlin、Jetpack Compose、Room、Python 网关、JUnit、Python unittest。

**Spec:** `docs/PRD-Multimodal.md`

## Global Constraints

- 无授权的界面描述性文字增量为零；仅添加功能必需的最短控件、数据标签和状态。
- 不启动模拟器；执行 JVM、Python、Android 源码编译和 Lint。
- 保留既有事实核查、UI 风格、可见区间统计和删除失效机制。
- 未知不表示零风险；接触不表示认同；内容情绪不表示用户心理状态。
- 不新增依赖，不升级版本，不推送；提交版本规则在用户授权下一轮推送时执行。
- 用户确认无真实 TEE 环境和模型产物。产品功能使用已有通用模型与明确标识的统计规则；不伪装自训练模型或机密计算完成。

## Review Focus

- 同作品反复采样或多模态附属记录，不制造独立支持数或情绪分母。
- 未知、冲突、被截断的论据关系不能当作重复或新增结论。
- 一天集中阅读、跨日新证据学习不产生长期重复提醒。
- 外部补全的响应必须受原文、网络配置与授权变更约束，不能污染已浏览历史。
- 旧 JSON、失效分析与无情绪字段记录仍可读；不把缺失视作中性。
