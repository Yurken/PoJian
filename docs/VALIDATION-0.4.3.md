# v0.4.3 观看记录修正

## 真机问题及修正

- 检查由辅助功能事件触发，并每2秒兜底一次；检查次数不是作品数。旧逻辑把系统界面、输入法和悬浮层的事件包名当作离开作品的证据，导致会话不断重置。现在依据当前活动窗口及采集授权判断。
- 当前窗口短暂缺失、没有文字或被系统界面遮挡时暂停计时，同一作品在15秒内恢复可继续原观看；不可见的间隔不补算。真实应用切换、锁屏、暂停采集仍结束观看。
- 小红书单图详情缺失已知资源ID时，使用可见作者和正文首条长文字提供启发式作品身份。多图图片文字不冒充固定标题，仍使用原多图连续性策略。
- 小红书包含至少两条“笔记/视频…来自…赞”卡片的推荐列表不计作一篇已浏览作品，不整屏提交观点核查；目前应打开单篇详情浏览。不是所有平台、版本的推荐列表都能识别。

## 原有数据

仓库首次读取时在事务和采集锁内整理历史数据，无破坏性数据库迁移：

1. 可以提取上述作品线索的旧未知身份记录补充平台内身份。
2. 仅相邻、同平台、身份一致、过滤界面计数后正文逐行一致、间隔不超过6秒且不重叠的记录合并。保留首条记录ID，将原始采样重新归属，不补算两条记录之间的空白时间。
3. 曾采集到的上述推荐列表保留在数据库，标记为recommendation_list；从浏览作品、统计和分析输入中排除。
4. 不跨另一篇作品强行合并；回看同一已识别作品保留另一次观看，但作品数量去重。无法识别的记录仍可能重复，不能承诺修复全部旧数据。

## 统计与验收

保留今日、过去24小时、最近7天三个范围；总计及各平台分别显示作品估计数、观看次数和估计停留时长。停留是可见检查的估计，不等于注视时长。

自动回归新增：真实单图文字及点赞变化、短暂节点缺失后恢复、不合并不同标题或长时间离开、推荐卡片识别、旧重复观看归并及原始采样保留、跨作品不合并、历史推荐列表排除、整理重复执行。

OPPO验收：覆盖安装同一预览版，打开同一篇单图笔记停留约20秒，确认一条观看且时长增加；改变点赞/评论计数后仍为一条；再打开另一篇作品确认数量增加；返回旧作品确认增加观看次数但不增加已识别作品数。分别检查三个时间范围的平台小计与总计。推荐列表不作为已完整浏览的单篇作品计数。

尚需OPPO真机回归。当前身份策略是启发式，平台真实作品ID尚未打通；同作者同标题、界面改版、评论页、倒序翻图、缺失作者等情形仍有局限。

本地验证结果：预览APK与测试APK构建通过；95项JVM测试通过；11项Android测试通过（WorkPersistenceTest、CapturePrivacyTest、SessionMigrationTest、RecordsGroupingUiTest）；Lint无错误，7项既有警告。模拟器覆盖安装并成功启动。OPPO测试尚未执行。
