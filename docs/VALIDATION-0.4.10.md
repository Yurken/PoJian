# v0.4.10 证据身份与历史比较

日期：2026-10-11。versionCode 17，Room 仍为 v6，安装 ID `com.zhiheng.app`。

本轮对照作品报告 2.4、2.5.4、2.6.3，修正“不同当事人的相似案例被当成同一论据”。案例新增仍与条件、解释是否扩展分开；同一观点保留同组，新增个体事实不证明行业全貌。

## 实际行为

- 网关、客户端和 Room JSON 共用可选 `evidence_actors`、`evidence_origins` 字段，每列最多 4 项、每项最多 80 字符，必须为该论据的连续原文。错误类型、重复、超限、空项、拼接和捏造跨度拒绝整次抽取或整行保存。旧接口和旧 JSON 缺列时兼容空列表，无需数据库迁移。
- 身份比较位于论据层，不把案例当事人塞进主张对象以人为拆散观点。不同具名当事对象保留为个体事实补充；同一案例跨应用、帖子或账号仍能命中早期记录。发布账号和作品编号不证明材料独立。
- 身份缺失、匿名代词或原材料关系不清楚时保留待定，不把不匹配自动称为新案例。同名仍须比较论据中的数字、否定及已识别时间和地点。姓名编号、材料标题年份先从数值对照中排除，标识内部连字符保留；本地提取超过 4 个身份时转待定，不静默截断后认定重复。
- 日报和实时提醒共用身份门控，按实际浏览时间比较，实时每项至多回查最近 120 个同范围候选；同一音频会话、同一时刻的采样不凭条数构成历史重复。案例与原材料线索可在详情及 TXT/PDF 引文中回查。
- 旧数据的本地身份提取只覆盖明确的“某对象的本人／个人记录或亲身经历”和具名材料线索。时间和地点识别使用有限词表与显式范围格式；尚未完成全实体、别名、指代、事件编号和多语言语义对齐。原文出现相同姓名或材料名也不证明现实世界身份相同；模型的角色抽取仍可能错误。
