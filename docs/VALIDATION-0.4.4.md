# v0.4.4 抖音页面适配

基于2026-10-09在OPPO上的页面结构对照实现，原始截图和XML保存在本机app/build/phone-diagnostics，不提交包含用户浏览内容的原始材料。

## 本次功能

- 抖音普通视频从user_avatar的描述读取作者，title作为后备；文案读取desc。
- 展开文案页使用g9q作者和g8t文案。下方推荐卡片的user_name不作为当前作者。
- e4u评论标题与back_btn共同识别评论面板；评论者复用的title不作为视频作者。只有存在本次进程中同平台视频上下文时，评论才能附属于原视频。
- 同平台同作者，截断文案与完整文案有至少16字符的前缀对应时，保留原观看身份。移除“... 展开>”尾部和展开页日期标签，点赞计数不参与身份。
- 评论、返回视频、展开和收起文案继承原观看ID、作品键与停留累计。切换作者或不同文案新建观看。
- 抖音菜单、缺少当前作品作者/文案的页面不新增作品；未知页面暂停计时，不将未知时间补算为观看。

## 验收方式

JVM回归覆盖视频→评论→返回的ID、作品键与时长守恒；文案展开与收起；推荐作者不污染当前身份；同作者不同文案；完整文案共同前缀但结尾不同；菜单与无上下文评论。

OPPO覆盖安装同一预览版后，选择抖音并启用采集：打开一个视频等待6秒，打开评论并停留6秒，关闭评论，展开和收起文案。该过程应是一条观看、一个作品。切下一视频应新增作品；菜单不应新增记录。核对概览总计和平台小计。

## 边界

当前是依据所采集抖音版本节点的启发式适配，没有真实平台作品ID。同作者同文案的视频、截断文案无法区分的作品、未观察到的快速切换、APP更新或进程重启仍可能误计。不能宣称全平台不重不漏。评论被保存在原观看的可见文字与采样里，目前尚未与视频正文分开做语义归属。历史未知记录不会自动补成精准作品ID。

本版只修改抖音适配，小红书仍沿用现有实现，需要单独采集真机页面结构验证。
