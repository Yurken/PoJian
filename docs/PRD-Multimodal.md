# 破茧：跨应用多模态监测与实时核查

更新：2026-10-08。此规划替代“音频优先的短视频回顾”产品路线。语音链路保留为输入能力，图文笔记、短视频和文章是并列场景。本轮源码实现与未完成事项见 [设计对照](IMPLEMENTATION.md)，不将规划目标写成已验证成果。

## 1. 核心目标

目标一：监测已接触的信息环境是否出现持续的同观点、低新增论据和条件单一等线索。目标二：在用户浏览过程中，对可验证声明查找外部依据并及时提示具体矛盾。两条分析链路分别输出结果，不能用一个笼统的“内容好坏分”代替。

“女性独立”“某品牌是国产之光”等表达不能作为触发黑名单。系统不判断用户应当认同什么，不自动推荐相反观点；有价值的补充是可靠的新事实、条件与解释。

## 2. 产品结构

App 内以概览、发现、设置为一级导航。概览展示信息接触统计与两类分析状态；发现呈现观点观察、事实核查、证据与原文材料；设置管理应用范围、权限、分析开关、提醒与网关。录音进度、转写修订和文件导入只在采集工具或材料详情出现。

悬浮球承担即时交互。普通结果沉淀到发现；达到提醒条件才短暂展开，不抢焦点，默认无声音或振动。用户可以核查当前采样、查看依据或暂停全部监测。专题研究模式只抑制观点集中提示，不关闭事实矛盾核查。

## 3. 统一内容模型

长期目标是以内容条目而非录音会话为中心，将标题、正文、图片、字幕和口播绑定到版本化材料，再提取议题、对象、评价维度、观点、依据、条件、来源和时间。内容、接触事件、外部核查证据分别保存。同一篇笔记多次打开不产生多份独立来源，一段录音的多个切片不等于多个视频。

本轮以屏幕上下文、采样 ID、输入类型、音频会话和保守前台接触分组实现基础路由；尚未实现可靠的完整帖子 ID 与多图归并。遇到未知边界保留覆盖不足，不能假设用户看了未显示的图片或全文。外部检索材料只供核查，不能用来虚增用户接触多样性。

## 4. 输入与多模态

图文链路：所选应用的可见文字与关键画面 → 视觉/文字结构化 → 观点观察与声明取证。视频链路在此基础上增加端侧稳定语音转写。图片可以独立触发分析，无声视频同样保留画面输入。

本轮画面采用间隔采样、缩放压缩和相同画面去重；不是持续上传录像。Android 14+ 优先采集目标窗口，Android 11–13 使用显示截图后裁取目标区域，Android 10 仅保留文字与音频。安全窗口、拒绝内录和授权撤回均按不可用处理。

多模态的后续验收应覆盖：封面疑问与正文辟谣、后续图片补充否定条件、评论区反驳、图表口径不一致、字幕和口播冲突、静默图文、旧图配新事件。当前视觉模型提取文字不能代替全部这些语义能力，连续视频时序推理与真实性鉴伪仍需单独实现。

## 5. 两条分析链路

观点观察复用历史联合证据覆盖，分开统计观点集中与依据重复。新增的纯 Kotlin 策略要求足够接触和跨日覆盖，按议题、对象、维度和条件隔离，并支持未知归属和专题研究抑制。这些是可复现启发式，不是训练或校准过的诊断模型。

事实核查必须取得外部材料。流程为声明抽取、缓存检查、条件保留的中性检索、正文证据对齐、引文校验、分级结论。原话证明“内容说了什么”，不能证明“说得对”。没有原始资料、只有搜索摘要、取证失败或归属不明时，不得以模型记忆补出确定结论。

## 6. 费用与实时性

两个功能共享结构化输入，端侧转写不计语音 API 费用。当前有界队列、短时完全匹配缓存、画面间隔与双端额度只提供基础控制；一次网关请求最多一次抽取、一次搜索、一次证据对齐。每次最多抽取三条、核查一条，未核查部分必须显示。

实时意味着内容形成后持续处理，不承诺所有画面或所有声明即时完成。用户划走后的结果进入发现，不能错挂新内容。后续应测量首条可用结论延迟、队列丢弃率、每分钟浏览成本、视觉覆盖率和每小时误提醒次数，而不只统计请求是否成功。

## 7. 验收与研究重点

工程验收：图文无需录音即可发起视觉核查；播放转写稳定后自动入队；提醒可关闭、限频和静默；证据链接可打开；删除或更正使旧结果失效；无取证配置不冒充已核查。

模型验收：独立标注观点归属、条件匹配、事实可验证性、证据质量、证据对齐和提醒价值。报告精确率、召回率、未知覆盖与误提醒，不将编译或假上游测试当作准确率成绩。自研重点是观点—论据时序收窄、证据隔离验证和成本感知多模态调度，不是录音页面功能堆叠。

暂不将 TEE、联邦学习等复杂设施列为原型前置条件；仍保留明确启停、选择范围、凭据保护和删除能力。使用用户自己的 API 不改变内容实际发送到提供方的事实。
