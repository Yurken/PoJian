# 第三章 作品测试与分析

本章承接第二章的端云协同、证据约束、个人历史比较、时序论证图、机密计算与情绪分析设计，建立分层测试方案。当前评价重点为已经实现的采集与统计基础、模型网关以及本轮补充的版本化历史后端。测试记录将工程验证与模型效果评价分别处理：已运行的功能用例和本机微基准报告实际结果；尚未部署或训练的模块列出测试方法、数据与验收条件，不以设计示例代替实验结论。

## 3.1 测试目标与实施范围

### 3.1.1 测试目标

系统测试首先检查浏览材料能否以作品、接触事件和输入版本进入分析流程，验证重复上传、再次观看、片段补充及结果修订能否保持一致。随后检查窗口内作品数量、观看次数和可见停留时间的统计口径，并核对各项结论是否能够返回原文及对应修订。历史比较重点验证当前材料只使用此前已经观察且在该时刻可用的版本，避免将未来片段作为过去浏览的依据。

模型评价分别覆盖论证抽取、信息增量、长期接触模式和情绪诱因，不将主题集中、停留时间或内容情绪直接解释为用户的信息茧房状态或心理感受。安全评价对应第二章的可信边界、消息完整性、历史新鲜度和派生数据删除。只有已经具备相应环境并完成测试的性质，才纳入已实现结论。

### 3.1.2 当前实现范围

当前Android原型具有用户选择应用、无障碍文字采集、作品与观看记录、本地保存、时间窗口统计、原文回看、离线观点短语、数量柱形图及观点分组基础。既有网关具有文本或采样画面分析、检索取证、连续引文检查、预算限制与管理配置。外部模型返回结构化结果，不能据此认定第二章设计的对象条件对齐网络、质量门控、双路编码器、TGN及联合情绪模型已完成自主训练。

本轮新增历史后端以独立联调服务实现事件幂等、修订快照、严格过去历史、字面论据联合覆盖、基础候选图、窗口报告和删除后重算。该服务尚未连接Android上传流程，不改变现有生产网关；语义字段由调用方提供。数据库保存明文，未实现真实TEE、应用层机密协议、模型概率校准或持久分阶段任务队列。

## 3.2 测试方案与环境搭建

### 3.2.1 分层测试方案

测试分为模块、服务接口、历史一致性、端到端、性能和安全六个层次。模块测试检查字段约束、论据覆盖和区间运算；接口测试使用本机HTTP服务检查鉴权、状态码与报告下载；历史一致性测试构造重复、乱序、修订和删除序列；端到端测试以受控页面和真机浏览核对作品边界与报告。性能测试先评价无需外部模型的工程基础，再单独测量OCR、ASR、模型推理和图更新。安全测试按实际协议阶段开展，联调与真实硬件模式分别记录。

各项测试保留输入、预期、实际结果、程序版本和执行环境。合成数据、人工标注数据和真实设备操作记录分别管理。回归测试在代码变化后检查已有行为；人工验收用于发现自动用例未覆盖的真实页面变化，两者共同组成验证流程。

### 3.2.2 测试设备与软件环境

本轮服务端测试于2026年10月10日在Windows 11家庭版环境完成，系统版本为10.0.26200。处理器为Intel Core i7-1065G7，4个物理核心、8个逻辑处理器，可用物理内存配置约15.8 GiB。Python版本为3.12.6，测试框架为标准库unittest，数据库为Python内置SQLite；没有使用GPU或第三方训练框架。

接口测试由ThreadingHTTPServer绑定127.0.0.1及临时端口，在测试进程中启动和关闭。不同用户配置不同Token，由服务器映射到用户空间；请求体不得指定用户。业务输入和测试日志不包含真实个人浏览历史、模型密钥或检索密钥。文件恢复测试使用临时目录，在关闭数据库后重新打开并比较结果。

Android工程当前使用Kotlin、Jetpack Compose及Room，compileSdk与targetSdk为34，minSdk为29。既有验证曾使用Android模拟器和OPPO手机，但本轮没有重新测量真机采集准确率、系统耗电、温升和流畅度。因此，既有设备截图作为问题定位依据，不列作本轮新实验的准确率样本。

### 3.2.3 原型部署与复现方式

历史联调服务默认只监听本机8788端口，明确启用POJIAN_HISTORY_PROTOTYPE后方可启动。数据库路径与用户专属Token分别由环境变量配置。联调服务不随现有Linux生产部署自动开启；在建立传输保护、存储保护和密钥管理前，只使用合成或经授权脱敏的材料。

运行新增模块测试采用“py -3 -m unittest server.tests.test_cognitive_history -v”，运行全套后端回归采用“py -3 -m unittest discover -s server/tests”。微基准由server/bench_history.py生成JSON记录，保留Python和系统版本、输入规模、运行次数及各项耗时。当前算法标识为literal-history-baseline-v1，可与报告中的事件修订和输入摘要共同定位版本。

## 3.3 测试数据与评价口径

### 3.3.1 工程功能测试数据

新增测试使用人工构造的事件和主张。每条事件包含作品标识、事件标识、应用、修订号、开始与结束时间、修订可用时刻、可见文字及主张列表。主张保存议题、对象、立场、原句、论据、条件和首次观察时间。测试文本用于确认程序行为，例如“当前就业困难”和“招聘数量下降20%”；这些句子不是经外部核实的统计事实，也不作为语义识别金标。

时间边界数据包括跨窗口区间、零时长观察、相互重叠的事件、同时间事件和后到达的早期事件。版本数据包括相同输入重试、同修订不同输入、修订跳号、作品身份被改动、未来修订以及删除历史。隔离数据在两个用户空间内使用相同事件标识，检查是否发生越权读取或删除。

### 3.3.2 性能测试数据

微基准分别生成30、100和300条合成事件，每条对应一个不同作品，具有一个主张、相同议题与字面论据，可见区间长度均为100毫秒，起点间隔为1秒。该设置主要评价持续历史筛选和重复论据引用的工程开销。历史候选上限为50条。

数据写入内存SQLite，每个规模完成一次事件写入序列，并生成5次同窗口报告。报告耗时不包含网络传输、文件数据库刷盘、模型推理、GPU计算或TEE协议。写入P95由该规模的实际写入耗时排序取得；报告只有5次重复，报告最大值仅描述本次样本，不作为生产尾部延迟或服务等级承诺。

### 3.3.3 统计与判断口径

作品数按应用与作品ID组合去重，观看次数按事件ID计数，相同事件的多次修订只取窗口截止时刻可用的当前版本。可见时间取裁剪区间的并集，不把并行或重叠记录简单相加。这里的可见时间不等于真实阅读时间，也不用于推断用户对内容的认同。

观点统计保留议题、对象、立场和条件，多标签分别计算其覆盖作品数。各比例均以窗口内全部作品为分母，同一作品可属于多个观点，因此比例之和可能超过100%。没有主张的作品单列为未知；已提供主张的作品比例仅反映字段覆盖，不是经过模型验证的语义准确率。

字面比较只把所选历史中完全相同的论据单元标为已覆盖。当前立场、条件及全部论据都具有字面匹配时，才输出字面重复；未匹配输出待语义复核，没有当前论据输出证据不足。新颖性与真实性分别处理，不因未匹配历史就断言出现了可靠的新知识。

## 3.4 功能与一致性测试结果

### 3.4.1 幂等接收与输入修订

相同事件与修订重复提交时，第一次写入返回recorded，后续返回duplicate，报告中仍为一次观看。同一修订更改输入会返回409，避免重试隐式覆盖已经接收的材料。8个并发线程重复提交同一输入时，结果为1次新建和7次重复，数据库仅保留一个修订。

后续合法修订替换当前统计贡献，不增加观看次数。测试把一条事件从100毫秒扩展到500毫秒并修改立场，更新报告保留一次观看、500毫秒和新立场；查询较早截止窗口时仍读取旧修订。修订跳号、身份变化、时间倒退和超出容量的输入均被拒绝。

### 3.4.2 过去历史与迟到处理

先写入较晚事件再写入较早事件，比较按观察时间完成，较早事件不会引用未来材料。同时间事件也不互为历史。历史材料在当前观察时点之后被修订时，比较读取其此前可用版本。加入窗口终点之后的事件不会改变较早报告或其输入快照摘要。

在先收到新事件的场景中，首份报告显示初始材料；补入更早的相同依据后，重新生成报告能够识别字面重复。删除早期依据后，后续报告不再引用被删除事件。此处通过从保留输入完整重算实现一致性，不等同于第二章设计的受保护检查点恢复、局部图记忆重放或客户端两阶段提交。

### 3.4.3 论据覆盖与不确定状态

联合覆盖用例分别在两条早期材料中保存不同论据，当前材料包含两项论据时，两项均能回指各自历史，并形成字面覆盖。修改数据数值、条件或立场的对照用例不会被当作字面重复。没有论据的当前主张返回证据不足，不以空集计算“零增量”。

这些测试确认的是边界条件和可追溯性。字面匹配尚不能处理同义改写、隐含条件、作者引述后反驳以及原始来源复用。需要语义复核的状态也不表示已经识别出新增事实或相反观点。

### 3.4.4 统计口径与报告下载

同一作品的两次观看与一个未知作品构成三次事件、两个作品，未知作品占一个；已提供观点的作品占全部作品的50%。重叠区间采用并集，跨窗口部分按交集计算；同一作品不会作为自身的历史重复候选。多观点作品可出现200%的合计标签比例，报告明确注明多标签口径，避免将其误读为互斥饼图。

报告返回事件修订、原句位置、比较依据和内容/观点/论据/应用候选图。HTTP响应使用JSON附件，设置不缓存响应头，支持下载为PoJian-history-report.json。另一用户使用其合法Token只能得到自己的空报告，不能删除已有用户事件。数据库重新打开后报告结果与关闭前保持一致。

### 3.4.5 自动化测试汇总

本轮新增21项历史与接口测试全部通过，既有后端回归114项亦通过，合计135项，无测试失败。测试覆盖版本替换、幂等、并发重试、过去历史、迟到与删除重算、联合覆盖、未知分母、多标签、隔离、引用约束、图与原文追溯及恢复。该结果说明相应工程用例满足预期，不等于语义任务准确率为100%，也不覆盖所有第三方应用页面。

## 3.5 本机性能测试与结果分析

30条事件时，单次写入中位耗时为0.047毫秒、P95为0.067毫秒；5次报告生成的中位耗时为7.607毫秒、最大值为9.964毫秒。100条事件时，写入中位耗时为0.051毫秒、P95为0.066毫秒；报告中位耗时为41.338毫秒、最大值为53.165毫秒。300条事件时，写入中位耗时为0.056毫秒、P95为0.105毫秒；报告中位耗时为287.284毫秒、最大值为296.906毫秒。

三个规模的报告均返回与输入规模一致的去重作品数量。JSON大小依次为50803、286668和1002994字节。重复论据需要保留历史引用，报告体积随材料数量增长；生成过程对每个主张扫描可用历史版本，即使下游候选限制为50条，筛选本身仍可能产生接近平方级的工作量。

因此，当前方案适合作为小规模可复算联调基线，不宜直接据此配置多用户生产容量。后续应增加按用户、议题及事件时间的索引，分离原文与引用明细，采用分页、依赖索引与增量物化统计，并比较优化前后在相同数据下的开销。第二章中30台设备、平均每秒10个事件的容量示例尚未经过本轮验证。

## 3.6 安全性测试与机密计算验证计划

### 3.6.1 当前已验证的安全边界

接口验证未授权Token返回401，调用方不能通过请求体伪造用户身份。不同用户的读写与删除按服务器配置身份隔离。输入引用必须位于本次可见文本中，非法时间和字段被拒绝；日志不主动输出原文及Token。重复事件的幂等接收降低重试导致的重复计数，但没有实现加密协议层的序号抗重放。

上述用例是工程安全检查，不是完整渗透测试。SQLite仍保存明文，输入摘要不是带客户端锚点的Merkle检查点，文件恢复也不能证明宿主机快照回退可被检测。该原型不得用这些结果宣称服务提供方无法读取历史，或已经满足第二章可验证机密计算的安全目标。

### 3.6.2 待开展的协议及硬件测试

协议联调阶段应明确采用Mock证明，注入挑战重用、公钥替换、版本清单变化、错误测量值、AEAD密文篡改、序号重放与方向混用，核对密钥释放和任务执行是否被拒绝。状态测试覆盖客户端确认前后掉线、服务器未收到确认、旧快照恢复、多设备前驱分歧及删除后依赖重放。

真实CPU机密执行阶段应记录硬件、证明证书链、镜像测量、调试状态、模型与配置摘要，验证明文确实仅在终端与获准可信边界内处理。GPU机密执行需额外验证设备证明与CPU—GPU受保护链路。常规与机密执行在同一模型、输入和批量条件下比较握手、传输、推理、恢复和提交耗时。当前无对应硬件环境，结果标记为未测试。

## 3.7 核心模型与真机效果评价计划

### 3.7.1 多模态结构理解和阅读投入

论证数据按原始作品、评论线程和来源划分，标注对象、主体、主张、论据、条件、引用关系及证据位置。不同观察前缀属于同一划分，避免同一视频泄漏到训练与测试。评价采用字段与关系F1、主体归属正确率、证据定位、拒识覆盖及部分观察错误率；对比纯文本、直接拼接和完整模型，移除对象条件、质量门控及证据定位进行消融。

阅读任务另用受控页面记录正文与评论可见区间，由参与者回顾确认重点条目，具备条件时增加眼动参考。比较均匀分配、固定屏幕位置与融合交互线索的时间误差和条目定位，并验证总时长守恒。OPPO与其他目标机型需要复测图文滑动、视频暂停、文案展开、评论开关、切屏及锁屏，不用采样次数代替作品真值。

### 3.7.2 历史增量与时序论证图

历史数据必须含同观点新论据、换写旧信息、多条旧材料联合覆盖、条件扩展、引用后反驳及同源转载等样本。先评价历史候选召回率，再评价观点/论据关系macro-F1、五维增量及待定状态、原文依赖定位，区分错误出现在检索还是精判。当前字面基线作为对照，不填入训练模型效果。

长期序列使用多个有效观察日并记录采集覆盖；无观察日期标为缺失。将持续低增量接触与正常专题阅读作为不同对照，比较主题统计、观点统计、图特征基线和TGN。分别报告新用户隔离与同用户未来时间切分下的F1、误报、漏报、Brier分数、校准误差及各来源/议题分组结果。未取得金标和校准集前，不使用演示颜色或离线分数作为受影响程度。

### 3.7.3 情绪诱因与个人反馈

中文目标域标注情绪与原因跨度、持有者、对象、引用/否定、五维认知评价、处境和表达方式。公开数据仅提供已有字段监督，缺失标注不作为负例。按原始作品、完整视频、评论线程和来源隔离，并保留独立校准集。

评价报告情绪—原因配对F1、带类别配对F1、角色跨度F1、归属准确率、处境与表达方式macro-F1、适用性F1及有序误差。个人反应仅以自愿自报为标签，按用户早期反馈适配和后续记录测试，冷启动单独统计。内容焦虑表达、用户自报与模型估计分开呈现；当前未完成此训练与评价，不提供推测的准确率。

## 3.8 测试结论与后续改进

当前测试确认了版本化历史服务在合成输入下的幂等、时间边界、修订、隔离、统计和报告追溯行为，为第二章后续模型、图分析和安全协议提供了可测试的数据基础。135项后端测试与小规模本机微基准给出了本轮能够复现的工程证据。

系统尚未完成第二章全部研究方法。下一阶段先接通Android与历史服务，完善片段和主体归属、真实作品计数的人工验收以及数据库索引，再建立中文标注集和模型基线。真实TEE与机密GPU按照协议联调、CPU机密执行和GPU扩展逐步测试。最终参赛报告应在各阶段完成后补充实际数据和结果，保留当前证据范围，避免将可实现设计表述为已验证能力。
