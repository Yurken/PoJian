# v0.4.9 持久任务、可见区间与离线评测

日期：2026-10-11。版本 0.4.9，versionCode 16，Room v6。

本轮继续对照作品报告 2.3、2.5、2.6、2.9 推进客户端：让已记录的文字/音频任务能够跨进程恢复，记录正文和评论区域的实际可见区间，并建立有独立预期标签的评测入口。后端源码和部署配置没有变更。

## 具体行为与边界

- 文字/音频核查先与已有浏览记录及全部依赖快照关联，再写入 Keystore AES-GCM 加密任务副本。任务身份参与认证；不保存访问令牌、原声或原截图。副本明文上限 192 KiB，待处理容量 6，任务状态和去重索引最多保留 24 小时。
- Room 事务负责领取、租约、完成、取消和重试；总共至多尝试 3 次，网络/408/429/5xx 使用 5 秒、30 秒间隔重试，格式错误、认证失败和预算耗尽直接保留未完成状态。重试使用相同 HTTP 请求身份，每次真实请求仍占额度。当前服务端没有持久响应去重，不能宣称付费调用严格只执行一次。
- 应用进程再次启动时恢复未完成任务；活跃租约不被其他 Store 抢占。系统强制停止后不会自行启动；截图只在容量 1 的内存队列中，重启后重新采样。
- 明确保存空访问令牌后，重启保持空值；只有尚未配置时才读取构建默认令牌。真实进程测试发现并修正了旧的空值回退问题，服务指纹现在能保持一致。
- 授权和服务修订号持久保存。关闭再开启、改服务或改监测设置，不能恢复旧授权任务。全部依赖输入具有 FK 和变更触发器；改文后又恢复原文，旧租约仍作废。语义结果落库时在同一 Room 事务重新校验租约，防止旧结果复活。删除和完成串行，不增加作品数、访问数或时长。
- 单条输入因授权变化失效时只取消该任务，唯一消费者继续处理后续任务；真正的协程取消仍传播。删除当前可见作品后保持删除标记，时钟跳变或区间容量拆分不会把它重新插入。
- 屏幕上下文增加实例随机标识，重建后同应用、同窗口、同文字也不复用旧屏幕令牌。恢复结果可进入历史回顾，仍需当前屏幕绑定和两分钟时限才能主动提醒。
- 新采集记录保存正文/视频页面、评论区、未定位的实际可见区间。相邻稳定采样才连接，暂停空档不桥接；区域切换归未定位，时钟跳变和容量限制拆分访问并保留已知作品身份。小时统计按区间交集分配。旧记录仍保留原有整次估计，区域未知；损坏区间不会退回均摊。屏幕停留不等于注视、阅读、认同，评论区尚未分配到单条评论。
- 概览、发现、日报和 TXT/PDF 导出显示待分析或最近未完成状态。原文和已完成核查结果仍未额外加密；新任务副本的加密不代表原文库加密或 TEE/远程证明。

JVM 包含可见区间的总量守恒、评论继承作品但不继承区域、跨小时暂停、窗口裁剪、时钟调整、容量拆分、损坏数据及屏幕重建提醒回归。Room 设备用例覆盖 v5→v6 保留原数据、Keystore 密文重开、独立连接并发领取、有限重试、全部音频依赖、ABA 原文恢复、同事务语义写入及删除竞态。Compose 用例校验全天、逐小时、窗口裁剪和旧记录的区域显示；本地假 HTTP 服务覆盖先 503 再成功的实际消费者链。

设备验证使用新建的独立 Android API 37、arm64、16 KiB 页模拟器，1080×2400、480 dpi（360 dp），未操作既有模拟器或手机。完整设备测试中的 5 项 assumption 跳过为 3 项缺少真实模型/音频夹具的 ASR 用例，以及 2 项必须由恢复脚本分别指定阶段的用例；后两项已单独跨进程通过。

本地验证输出（构建产物，不纳入 Git）为 `app/build/reports/validation-0.4.9/instrumentation-final.txt`、`process-recovery.txt` 和 `capture-visibility-hour.png`。截图已检查，12 点视图正确显示未定位 4 秒，正文和评论区各 0 秒，暂停空档不计入停留。

复现构建：

```sh
JAVA_HOME=/path/to/jdk21 ./gradlew --offline --no-daemon \
  :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug \
  -PemergeAbi=arm64-v8a
```

进程恢复测试只在显式选择、已安装目标及测试包的独立临时模拟器上执行：

```sh
python3 scripts/check-monitor-recovery.py --isolated-emulator emulator-NNNN --adb /path/to/adb
```

脚本使用主机回环假 HTTP 服务、设备反向端口和两次独立 instrumentation，中间 force-stop 测试应用；第二进程须复用请求身份、保留一个原事件、生成有效语义且不触发旧屏幕提醒。它不适合在保留用户数据的设备运行。
