# 破茧

> 察觉观点重复，查证眼前信息。

当前版本 0.4.12 统一界面与导出报告文案，折叠长说明并突出主操作。延续有限数量同义比较和逐项历史覆盖：明确独立的事实合并或换序后可回查各自旧记录，数字仍绑定对象、指标与单位。日报、实时监测和观点时间线共用有限立场／条件比较，相对日历范围按观察时间对齐。案例身份或范围不清楚时保留待定。文字／音频任务支持加密持久队列、进程恢复与受限重试，小时统计按正文／评论区的可见区间切分。[离线标注评测](docs/OFFLINE_QUALITY_EVALUATION.md)保留固定输入、金标、完整混淆矩阵和误提醒分母。作品身份仍有启发式限制，详见[作品与观看统计](docs/WORK_VISITS.md)。实时核查和视觉能力仍需配置网关并开启相应开关。

破茧是一款面向图文笔记、短视频和文章浏览的 Android 信息环境监测与事实核查原型。它关注两件事：**接触的观点与论据是否持续单一，以及眼前的具体声明是否有可追溯的外部依据。** 录音、转写和画面采样只是材料入口，不是产品主角。

应用内分为「概览／发现／设置」：概览保留今天、七日和小时统计；发现分别展示观点重复线索与事实核查证据；设置管理范围、悬浮球、分析开关和费用上限。录音与模型下载下沉到设置中的「采集工具」。

## 浏览时怎样工作

在用户选定的应用中，悬浮球提供「核查当前内容」「查看证据与统计」「暂停全部监测」。平时贴边显示、可拖动，默认静音、不振动、不抢焦点。只有持续重复线索或具有外部引文的证据矛盾才可能主动展开；设置可调整冷却时间、每日提醒次数、提示时长、夜间免打扰和专题研究模式。

图文不需要先录音。可见文字进入本地观察和可选实时分析；另行开启关键画面分析后，当前可见图片可发送给视觉模型。播放音频仍在本机转写，稳定片段写入后可自动进入相同核查入口，不必等到整次录音结束。核查迟于切屏时保留到发现页，不应作为下一屏的结论弹出。

「女性独立」「某品牌是国产之光」等价值表达本身不是虚假信息标签。系统区分议题、对象、评价维度、观点、论据和条件；观察到重复不等于已经证明用户陷入信息茧房，看过也不等于认同。

## 开始使用

1. 在设置选择允许监测的应用，在系统辅助功能中启用「破茧浏览采集」，返回打开采集开关。默认不选择任何应用。侧载安装可能需要先允许系统的受限设置。
2. 按需开启云端分析、悬浮球和实时事实核查。新版[分析与取证网关](server/README.md)的模型与检索配置由服务端管理台维护；App 使用内置服务地址及构建注入的访问令牌。设置中的「云端分析」可独立关闭发送。没有检索配置时会显示「未完成核查」，不会以模型记忆冒充外部证据。
3. 图文或无声视频：另行开启「关键画面分析」，并在网关配置视觉模型。播放口播：进入「设置 → 采集工具」，下载约 31 MB 的中文模型，选择播放应用并完成系统授权。音频导入保留为备用入口。

**兼容范围：** 文字与播放音频面向 Android 10+；本次关键画面采样使用辅助功能截图 API，需要 Android 11+，Android 14+ 优先截图目标窗口。悬浮球使用辅助功能覆盖层，与辅助功能授权绑定，不另建隐蔽采集服务。播放内录受来源应用策略限制，受保护的画面可能无法采集；不会绕过这些限制。

## 核查与费用

新版 `/monitor` 网关先抽取最多三条声明，再对其中最多一条事实声明检索网页正文并对齐证据，返回来源、连续引文和结论。观点、未核查、证据不足、资料支持、证据矛盾和证据分歧分别保留。取证失败、上下文不明或引文不匹配不会输出确定的真假提醒。

当前采用有界队列、完全相同输入的短期缓存、重复画面去重、画面采样间隔、每日画面额度和共享请求额度控制成本。**一次网关请求可能包含多次模型与检索调用，不等于一次模型计费。** 未显示部分、未采样帧和超出预算的声明没有被核查；没有提醒不代表内容真实。

已关联本地原文的文字和音频任务先以系统密钥库 AES-GCM 密文保存，最多 6 项、保留 24 小时、总共尝试至多 3 次；应用进程再次启动时恢复。授权与服务修订、原文或作品身份变更、删除会作废旧任务。每次真实重试仍占请求额度，当前网关未提供持久响应去重。画面原始字节只在短期内存队列中，退出后需要重新采样；系统强制停止后不会自行唤起应用。

## 构建与测试

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
python -m unittest discover -s server/tests -v
bash scripts/check-monitor-core.sh
```

首次 Android 构建会下载并校验固定版本的 sherpa-onnx 推理库。应用 ID 与数据库文件名保持不变；Room v5→v6 增加持久任务和可见区间，保留原有作品、观看、采样、结构观点和音频记录。旧记录的区域时长保持未知。使用相同安装身份、相同签名的安装包覆盖安装，不要先卸载。独立预览包应更新之前的预览版，不用于覆盖已放弃开发路线的旧实验包。构建特定设备包可使用 `-PemergeAbi=arm64-v8a`。

## 数据与边界

实时核查和画面分析默认关闭；带构建访问令牌的版本默认启用云端连接，可以在设置中关闭「云端分析」。手动核查或生成音频回顾可能发送必要文字；自动发送另外受实时核查、画面分析和所选应用范围约束。原声音频不上传，截图只作短时输入，不保存为原始图像文件。系统录音与授权提示保留。服务端保存模型与检索密钥，手机用系统密钥库保护访问令牌；正文、结构化观点、视觉模型提取文字和核查结果未额外加密，可在本机清除。

加密待分析队列只保护新增任务副本；原文库和已完成结果的加密、TEE 及远程证明仍待实现。正文／视频页面、评论区和未定位时间表示采样区间的屏幕停留，不等于注视、阅读或认同，也尚未分配到单条评论。

云端结果与原事件编号、完整文字快照及生成时间关联，只采用能够逐字回查的观点原句和论据。原文增长或更正后旧结构结果失效，删除浏览记录会级联删除相应结构结果；清除核查结果也会清除结构结果，原文采集记录保留。没有有效模型结果时使用本地规则候选，成功但没有提取观点的结果保持未知。模型结构覆盖只说明保留记录中哪些采样获得结果，不代表整篇内容或全部设备浏览已被分析；每次仍最多抽取三条声明。历史论据比较仍采用本地规则。

这是工程原型，不是已经验证准确率的信息茧房诊断器或视频鉴伪系统。当前仍缺少完整的跨页笔记归并、可靠的推荐流/搜索入口识别、精确声画对齐、连续视频时序推理和经过标注校准的提醒阈值。视觉文字由模型提取，可能有错；不能用引文字符串检查替代真实性验证。

## GitHub APK 打包

GitHub Actions 的 **Build APK** 流水线只执行 `:app:assembleDebug`，上传可安装的通用 Debug APK；不运行测试、不部署服务器。主分支构建成功后自动创建 GitHub Release，并附上可直接下载的 `PoJian.apk`；开发分支仅上传 Actions 产物。主分支或 `dev/**` 分支修改 Android 构建相关文件时自动触发，也支持手动运行。

优先在仓库 **Releases → 最新版本 → Assets** 下载 `PoJian.apk`。也可在 **Actions → Build APK → 成功的运行 → Artifacts** 下载 `PoJian-apk-运行编号`，解压后得到 APK，保留14天。可选仓库 Secret `POJIAN_SERVICE_TOKEN` 用于注入已有的网关访问令牌，未设置时为空；模型与检索密钥仍留在服务端。

流水线使用 GitHub 临时环境自动生成的 Debug 签名，未配置持久签名，因此不同运行的 APK、与本地签名 APK 之间可能无法覆盖安装。需要持续升级并保留数据时，应另行配置固定签名；遇到签名冲突不要直接卸载有数据的旧版本。
