## V0.2.1 连续浏览会话

事件触发与每 2 秒检查仍用于感知窗口，但检查次数不再等于记录条数。同应用连续相同正文（忽略短计数行）更新同一条会话的结束时间、估计可见停留时长和检查次数。数字证据变化保留；不同正文、离开应用、暂停、锁屏、节点不可读或超过 6 秒断档会结束会话。时长只累加相邻有效检查间隔，不外推最后一次检查之后的时间，不能代表实际阅读或理解。相似度规则仍可能错误拆分或合并，没有文章 ID 或视频 ID。

数据库从版本 1 无损迁移至版本 2。旧记录保留，停留时长未知；分析仅合并相邻同应用、间隔不超过 30 秒且稳定正文一致的旧快照。返回同内容算新会话。记录页、观点详情和 PDF/TXT 索引显示估计停留时长；同一会话多个观点共享时长，不可相加。统计页的应用占比仍按保存记录数，旧数据来源占比仍受旧快照频率影响。

覆盖安装后重新执行分析并导出报告。不要卸载或清空数据。

# 知衡 ZhiHeng — V0.2 离线可解释分析原型

本工程是独立 Android Studio 工程。Kotlin + Jetpack Compose + MVVM + Room；applicationId/namespace `com.zhiheng.app`，minSdk 29，compileSdk/targetSdk 34。本机同时安装了 android-36.1，首版选择完整整数 API 34，与本机已有 AGP 8.5.2 工具链配合。不含 AI、FastAPI、MediaProjection、TEE 或网络上传。

## 打开和运行

1. Android Studio → Open → 选择 `E:\Projects\ZhiHeng` 工程根目录。
2. Gradle JDK 选择 JDK 17 或 21（本机 `D:\Program Files\Java\jdk-21`）；等待 Gradle Sync。首次同步需要下载未缓存的依赖。
3. SDK Manager 确认 Android 14/API 34 和 Build Tools 34.0.0 已安装。`local.properties` 已写入本机 SDK 地址，换电脑时修改或让 Android Studio 重新生成。
4. 连接 Android 10+ 手机并开启 USB 调试，或启动 API 29+ 模拟器，选择 `app`，点击 Run。
5. 命令行也可执行 `./gradlew.bat assembleDebug`。产物为 `app/build/outputs/apk/debug/app-debug.apk`，是调试签名安装包；正式比赛发布签名需后续配置。

## 手机启用与测试

1. 打开知衡，进入底部「我的」，阅读采集说明；首次安装默认「允许采集」关闭。
2. 点「前往系统辅助功能设置」，在「已安装的应用/下载的服务」中找到「知衡浏览采集」，主动启用。不同品牌入口名称会不同。
3. 如果侧载 APK 在 Android 13+ 被系统限制，进入系统「应用信息 → 知衡 → 右上角菜单 → 允许受限设置」，再回到辅助功能设置。只在确认安装来源可信时操作；部分厂商还有后台运行设置。
4. 返回知衡「我的」，打开「允许采集」。打开浏览器，浏览一段不含私人信息的文字，停留约 1 秒、滚动、再停留。
5. 返回知衡 → 底部「记录」，应看到应用名称（无法识别时显示包名）、手机本地时间以及文字。展开全文可查看包名和事件类型。
6. 暂停采集后重复浏览，应不新增记录。重启知衡后原记录应仍在。清空按钮带确认，并暂停采集。
7. 手机系统关闭辅助功能服务后，回到知衡，状态应显示未启用；再次开启服务后可以继续测试。

## 项目结构

界面采用浅灰背景、白色圆角卡片、蓝绿图表以及底部三个图标入口：

- **概览**：过去 24 小时/最近 7 天切换，点击分析后展示离线规则提取的主题、观点候选、依据变化、小时引文回顾和长期重复线索；保留应用来源环图及排行。可保存 PDF 或完整文本报告。
- **记录**：最新 200 条记录，支持展开原文及事件信息。
- **我的**：采集开关、辅助功能设置入口、清空数据、隐私说明和版本说明。

来源统计使用全部保留的 Room 数据，最多 5000 条，不受历史列表 200 条显示上限影响。24 小时统计使用滚动时间窗口；7 天按手机本地日期统计包含今天的七个自然日。环图最多六组，来源较多时显示前五个应用和「其他应用」。记录数不等于阅读次数，没有估算浏览时长或认知评分。应用来源不等于作者、媒体或原始出处，应用数量不能直接证明信息茧房。应用名称读取失败时回退包名，无需全应用查询权限。升级安装不清空数据库。

## V0.2 分析与下载报告

1. 先确认「记录」已采到正文，而不只是按钮标签。
2. 在「概览」选择过去 24 小时或最近 7 天，可填写浏览目的，点击「分析」。分析只在你主动点击时进行，截取当前已保存记录，不需要网络、API 密钥或服务器。
3. 查看观点候选、主题占比与依据变化。点击候选引文查看事件编号、当前与先前原文、条件、引用/转折线索。比例分母是提取候选数，不是停留时间或独立帖子。
4. 查看「信息茧房观察」。不足 3 个自然日或少于 8 个不同观点事件的同主题，不提供持续窄化线索判断。未触发规则不代表不存在信息茧房。
5. 页面下方「下载观察报告 → 保存 PDF / 保存文本」，选择手机 Download/下载或其他目录；系统文件管理器中可打开对应报告，无需存储权限。
6. PDF 包含统计与观察，以及最多 100 个候选的引用附录；文本报告含本次分析的完整索引。文件记录分析时间、观察区间、分母、方法版本、数据缺失和限制。
7. 新采集记录不自动并入已生成报告，点击重新分析即可更新。分析快照由 ViewModel 在本次进程内保留，应用进程重启后需要重新分析；已导出文件不受影响。清空本地历史也不会删除外部已导出报告。

### 离线算法范围

文本清洗 → 排除桌面与常见按钮 → 合并同应用 90 秒内相同清洗文本 → 词表主题识别 → 8–240 字判断句候选（每快照最多 6 个） → 同屏依据/条件片段 → 按浏览时间与同主题历史比较 → 可核查的重复观察。

比较使用字符二元组相似度（观点 0.65、依据 0.85），保留否定、时间和部分地区/人群条件；最多比较最近 120 个同主题候选。信息变化分为首次观察、新增依据片段、依据近似重复、条件不同以及增量未知。没有依据不当成低增量；同观点出现新片段不简单标为重复。引用/转折归属未知，不推断作者或用户认同。

重复线索需同主题至少 8 个不同事件、覆盖至少 3 天，近似措辞最大组至少 70%，依据重复至少 60%。这是未经数据校准的工程基线，不是心理诊断、事实查证或科学风险评分。专题研究本身不是异常。浏览目的只作为报告解释背景，未参与阈值调整。

仅支持预设七类主题，未知主题、短评和娱乐可能不产生观点候选。同屏依据不一定真正支持对应主张，规则不具备完整语义理解。新片段不等于真实的新证据。主张与历史事件关联作为可核查索引，尚不是第一章规划的双路模型或时序图学习。也未实现多模态、阅读投入、情绪归因、机密计算和 TEE。后续模型应通过接口替换当前纯 Kotlin 分析器，并用标注样本评估。

代码：`analysis/CognitiveAnalyzer.kt`、`analysis/AnalysisState.kt`、`analysis/ReportExporter.kt`、`ui/AnalysisCards.kt`。数据仍使用现有 Room 表，升级无需破坏性迁移。PDF 为原生 Android PdfDocument 分页，文本为 UTF-8，系统文件选择器完成导出。

## 数据路径与采集策略

系统 AccessibilityEvent → 400ms 延迟合并（连续事件不无限推迟）/启用时每 2 秒补充检查 → `rootInActiveWindow` → 根据窗口实际包名过滤 → 深度遍历节点 → 可见文本/内容描述 → Repository → Room → Flow → ViewModel → Compose。

监听窗口状态变化、窗口变化、滚动、窗口内容变化；不订阅输入文字事件。启用交互窗口和非重要节点查询，仍只提取可见且与屏幕相交的文字；跳过 password/editable 子树。忽略自身、SystemUI、系统设置与部分常见键盘包名。节点遍历最多 1500 个、深度 40、文本最多 16000 字符。同应用连续相同正文合并为一条浏览会话，更新估计可见停留时长。写入互斥，避免事件和定时检查同时存储相同文本。每条记录保存 packageName、毫秒 Unix timestamp、eventType 整数、visibleText，以及 endTimestamp、durationMillis 和 sampleCount（旧记录这些字段为 0，时长未知）。定时检查沿用最近一次事件类型，不应将该值理解为新事件一定发生。数据库最多保留最新 5000 条，界面展示最新 200 条。后台服务不保留系统事件对象；挂起窗口变化后重新读取当前窗口。

## V0.1.1 采集排障

「我的 → 采集诊断」展示系统授权、实际服务连接、当前进程收到的事件数、最近浏览包名、检查时间、保存时间和检查结果。诊断不保存正文，进程重启后诊断计数会重置，已有 Room 记录保留。

系统权限判断同时参考 AccessibilityManager、系统启用服务配置及服务连接回调，不把开关打开等同于服务已运行。请开启「知衡浏览采集」服务本身，不仅是系统辅助功能菜单或快捷按钮。升级安装后若未连接，手动关闭并重新启用服务，再返回知衡。

先使用浏览器普通文字页面测试，停留数秒并滚动。若正常而抖音/小红书无正文，查看诊断是否报告节点为空或没有可读文字；图片和视频本体没有 OCR/录屏支持。若服务未连接，则先排查系统服务授权及后台管理，不能直接归因于应用节点限制。OPPO/ColorOS 入口名称因系统版本不同而变化，请搜索「辅助功能」，找到下载应用/已安装服务中的「知衡浏览采集」。

退出到模拟器主屏幕后，应用一般在向上滑动打开的应用列表中，Android Studio 安装不一定在桌面创建快捷方式。长按「知衡」图标可拖至桌面。

## 能力和限制

- 这是用户授权的跨应用可见文字采集实验，不是完整浏览历史或真实注意力检测。按钮、标题、评论等可能混在正文中；内容描述可能不等同于屏幕文字。
- 部分应用、WebView、Canvas、SurfaceView 和视频不会提供可读节点，可能无记录或仅有少量文字。空结果不存储，不应解释为用户没有浏览。
- 连续变化页面使用有界事件合并和定时检查；定时检查沿用最近事件类型，时间是窗口提取后的时间，不能作为精确浏览时长。
- 已实现离线文本规则的主题/观点候选、依据片段变化、重复线索与报告；未做 OCR、录屏、音频采集、语义模型、多模态或机密计算。
- 开关存入 SharedPreferences。系统是否启用服务由 AccessibilityManager 获取，回到应用时刷新；系统启用不保证厂商不会终止服务。
- 不声明 Internet、存储、录音或录屏权限。BIND_ACCESSIBILITY_SERVICE 是服务端的系统绑定保护，不是普通运行时授权。
- 数据存于应用私有 Room 数据库，禁用系统备份；尚无额外数据库加密。页面正文可能含敏感信息，过滤输入框无法保证完全排除所有私人内容。未提供全应用白名单，建议仅在受控测试时开启。
- 当前为竞赛原型。辅助功能用于非无障碍用途的分发需独立审视应用商店政策；本工程不代表已满足商店上架要求。
