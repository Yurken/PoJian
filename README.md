# 破茧 PoJian

> 察觉观点重复，查证眼前信息。

破茧是一款 Android 信息环境监测与事实核查原型。它回答两个问题：

- **接触的观点与论据是否持续单一**——识别跨应用、跨时间重复出现的观点与论据，提示信息茧房线索；
- **眼前的具体声明是否有外部依据**——对事实性声明检索公开网页并对齐证据，给出带连续引文的核查结论。

录音、转写与画面采样只是材料入口，不是产品主角。

**当前版本 0.5.10** · Android 10+ · [更新日志](docs/CHANGELOG.md)

## 功能特性

| 能力 | 说明 |
| --- | --- |
| 观点重复监测 | 区分议题、对象、评价维度、立场与条件；数字绑定对象、指标与单位，支持有限同义比较与逐项历史覆盖 |
| 实时事实核查 | 网关抽取声明 → 检索网页正文 → 对齐证据，返回来源、连续引文与结论；证据不足时保留未知，不输出真假断言 |
| 多模态采集 | 可见文字本地观察；关键画面先经端侧中文 OCR，必要时送视觉模型；播放音频本机转写（sherpa-onnx，模型约 31 MB） |
| AI 词云与统计 | 概览页提供今天／七日／小时统计与近期接触词云，基于已保存的 AI 分析结果聚合 |
| 低打扰交互 | 悬浮球贴边显示、不抢焦点；仅持续重复或证据矛盾时主动提醒，支持冷却、每日上限与夜间免打扰 |
| 应用自动更新 | 服务端代理私有 Release，校验 SHA-256、包名与固定签名后交系统安装 |
| 本地优先存储 | 文字／音频任务以 AES-GCM 加密队列持久化，支持进程恢复与受限重试；原声与截图不上传、不落盘 |

## 界面结构

应用分为三个主页面：

- **概览**——今天、七日和小时统计，近期接触词云与茧房动效；
- **发现**——「观点重复」与「事实核查」分列，卡片突出主题与原句，支持跨应用回查历史记录；
- **设置**——采集范围、悬浮球、分析开关与费用上限；录音与模型下载收在「采集工具」。

## 开始使用

1. **授予采集权限**：在设置中选择允许监测的应用（默认全不选），在系统辅助功能中启用「破茧浏览采集」，返回后打开采集开关。侧载安装可能需要先允许系统的受限设置。
2. **按需开启云端能力**：云端分析、悬浮球、实时事实核查各自独立开关。模型与检索配置由[服务端管理台](server/README.md)维护；未配置检索时显示「未完成核查」，不以模型记忆冒充外部证据。
3. **可选采集工具**：图文画面分析需开启「关键画面分析」并在网关配置视觉模型；口播转写需下载约 31 MB 中文模型并完成系统录音授权；音频文件导入保留为备用入口。

**兼容性**：文字与播放音频支持 Android 10+；关键画面采样使用辅助功能截图 API，需 Android 11+（Android 14+ 优先截图目标窗口）。播放内录受来源应用策略限制，受保护画面不绕过、不采集。

## 工作原理

```text
浏览内容 ──► 本地观察（文字 / OCR / 转写）
                │
                ▼
        /monitor 取证网关
          抽取声明（≤3 条）
          检索事实声明（≤1 条）
          对齐证据（连续引文）
                │
                ▼
     结论分级：观点 / 未核查 / 证据不足 /
               资料支持 / 证据矛盾 / 证据分歧
                │
                ▼
     本地历史比较（同义、立场、条件、逐项覆盖）
                │
                ▼
     发现页展示 + 满足条件时低打扰提醒
```

**费用控制**：有界队列、相同输入短期缓存、重复画面去重、采样间隔、每日画面额度与共享请求额度共同控制成本。注意：一次网关请求可能包含多次模型与检索调用，不等于一次计费；未采样帧与超预算声明不会被核查，**没有提醒不代表内容真实**。

## 构建与测试

```bash
# 客户端：单元测试 + Debug 包
./gradlew :app:testDebugUnitTest :app:assembleDebug

# 服务端：网关测试
python -m unittest discover -s server/tests -v

# 监测核心回归
bash scripts/check-monitor-core.sh
```

构建前请先按[固定签名配置](docs/ANDROID_SIGNING.md)恢复项目密钥与本地 `keystore.properties`——Debug 与 Release 共用同一签名，配置缺失时构建直接失败。首次构建会下载并校验固定版本的 sherpa-onnx 推理库；构建特定设备包可加 `-PemergeAbi=arm64-v8a`。

**覆盖安装**：应用 ID（`com.zhiheng.app`）与数据库文件名保持不变，当前 Room 为 v7。请使用相同签名的安装包覆盖安装，不要先卸载。

## 发布与分发

- **CI 流水线**：GitHub Actions「Build APK」在主分支或 `dev/**` 修改构建相关文件时自动执行，产出通用 Release APK；主分支存在指向当前提交的 `v<versionName>` Tag 时发布 GitHub Release（含 `PoJian.apk` 与更新清单 `update.json`）。
- **版本与 Tag 规则**：每次已授权的推送递增 `versionName` 补丁位与 `versionCode`，并创建同名附注 Tag 一并推送。
- **下载渠道**：优先从 **Releases → 最新版本 → Assets** 下载 `PoJian.apk`；也可在 **Actions → 成功运行 → Artifacts** 下载（保留 14 天）。0.5.4 及之后的安装包支持应用内自动更新。
- **历史签名说明**：本地与 CI 自 0.5.4 起共用固定签名，可连续覆盖升级；更早版本使用已丢失的临时签名，无法保证直接覆盖，请在验证数据备份前保留旧应用。

CI 需要仓库 Secret `POJIAN_SERVICE_TOKEN` 及[四项签名 Secrets](docs/ANDROID_SIGNING.md)，缺失即停止构建；模型与检索密钥仅保存在服务端。

## 数据与隐私

- 实时核查与画面分析**默认关闭**；「云端分析」可在设置中独立关闭，关闭后不向服务端发送内容。
- 原声音频不上传；截图只作短时内存输入，不保存为原始图像文件；画面文字优先在端侧识别。
- 待分析任务副本以系统密钥库 AES-GCM 加密保存（最多 6 项、24 小时、至多 3 次尝试）；访问令牌由系统密钥库保护，模型与检索密钥仅存服务端。
- 正文、结构化观点与核查结果存于本机、未额外加密，可随时清除；删除浏览记录将级联删除对应结构结果。

## 已知边界

这是一个工程原型，**不是**已验证准确率的信息茧房诊断器或视频鉴伪系统：

- 屏幕停留只表示采样区间内的页面可见，不等于注视、阅读或认同；评论尚未定位到单条。
- 作品身份识别为启发式，同作者同文案、快速切屏等场景可能误计，详见[作品与观看统计](docs/WORK_VISITS.md)。
- 视觉与 OCR 文字由模型提取，可能有错；引文匹配只说明文字出处一致，不能替代真实性验证。
- 待实现：跨页笔记归并、推荐流／搜索入口识别、精确声画对齐、连续视频时序推理、经标注校准的提醒阈值；原文库加密与 TEE／远程证明仍在规划。
- 本地历史规则的离线评测保留固定输入、金标与完整混淆矩阵，见[离线标注评测](docs/OFFLINE_QUALITY_EVALUATION.md)。
